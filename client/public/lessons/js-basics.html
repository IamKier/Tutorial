JavaScript: the basics Basics

JavaScript is the only language that runs in a browser, and with Node it runs on servers too. That is why this project is JavaScript from top to bottom — one language for both halves.

Where to run it

Press F12, open the Console tab, and type. It evaluates immediately, which makes it the fastest place to test anything in this lesson. For longer code, use the <script> block in your scratch file. 

console.log('hello');           // prints to the console
console.table([{a: 1}, {a: 2}]); // prints an array of objects as a table
console.error('something broke');

Variables

const name = 'Kier';    // cannot be reassigned
let count = 0;          // can be reassigned
var old = 'avoid';      // legacy — different scoping rules, causes bugs

Use const by default and switch to let only when you genuinely reassign. It is not about being strict — a const tells the next reader that this value never changes, which is one less thing to track while reading.

const is not "frozen"

const stops the variable being pointed at something else. It does not stop the thing it points at from changing. So const list = [] then list.push(1) is completely fine — you are modifying the array, not reassigning the variable.

Types

'text'  or  "text"  or  `text`     // string
42      3.14                        // number — just one numeric type
true    false                       // boolean
null                                // deliberately empty
undefined                           // never given a value
[1, 2, 3]                           // array
{ name: 'Kier' }                    // object

Backticks are template literals, and they are the ones you want:

const name = 'Kier';
const greeting = `Hello, ${name}. You have ${3 + 4} tasks.`;

// They can also span lines
const html = `
  <li>${name}</li>
`;

Comparison, and the one rule to remember

1 === 1      // true
1 === '1'    // false — different types
1 == '1'     // TRUE — == converts types first. Do not use it.

'' == false      // true    ← nonsense like this
null == undefined // true    ← is why == is avoided
[] == false      // true

Always use === and !==. The double-equals version applies a table of conversion rules nobody has memorised and everybody has been bitten by.

Truthiness

These eight values are falsy. Everything else is truthy:

false, 0, -0, 0n, '', null, undefined, NaN
if (title) { }        // runs unless title is empty or missing
if (tasks.length) { } // runs unless the array is empty
The empty-array trap

[] and {} are truthy, even when empty. if (tasks) is true for an empty array — check tasks.length instead. This catches everyone at least once.

Functions

// Declaration
function add(a, b) {
  return a + b;
}

// Arrow function — what you will see most in modern code
const add = (a, b) => a + b;

// With a body
const greet = (name) => {
  const message = `Hello, ${name}`;
  return message;
};

// Default parameter
const greet = (name = 'friend') => `Hello, ${name}`;

A one-line arrow function returns its expression automatically. Add braces and you must write return yourself — forgetting that is a common source of "why is this undefined".

Arrays

const tasks = ['write', 'test', 'ship'];

tasks.length        // 3
tasks[0]            // 'write' — counting starts at 0
tasks.push('deploy')      // add to the end
tasks.includes('test')    // true

The four methods that matter

These four do most of the data work in any real application. All of them return a new array and leave the original alone. 

const tasks = [
  { title: 'Write', done: true },
  { title: 'Test', done: false },
  { title: 'Ship', done: false },
];

// map — transform every item
tasks.map(t => t.title);
// ['Write', 'Test', 'Ship']

// filter — keep the ones that match
tasks.filter(t => !t.done);
// [{Test}, {Ship}]

// find — the first match, or undefined
tasks.find(t => t.title === 'Test');
// {title: 'Test', done: false}

// reduce — boil the list down to one value
tasks.reduce((count, t) => t.done ? count + 1 : count, 0);
// 1

They chain, and that is where they get powerful:

const titles = tasks
  .filter(t => !t.done)
  .map(t => t.title.toUpperCase());
// ['TEST', 'SHIP']

Open client/src/hooks/useTasks.js and you will find every one of these. Learning them well is the single biggest jump in JavaScript fluency. 

// Also useful
tasks.some(t => t.done)     // is at least one done?
tasks.every(t => t.done)    // are they all done?
tasks.sort((a, b) => a.title.localeCompare(b.title))  // ⚠ sorts in place

Objects

const task = {
  id: 'abc',
  title: 'Write the lesson',
  done: false,
};

task.title           // 'Write the lesson'
task['title']        // same, useful when the key is in a variable
task.done = true;    // set
task.priority = 'high';   // add a new key
delete task.priority;

Optional chaining

const city = user.address.city;    // 💥 if address is missing
const city = user.address?.city;   // undefined, no crash

const name = user.name ?? 'Anonymous';  // fallback only for null/undefined

?? is different from ||, and the difference matters: || falls back for any falsy value, so count || 10 gives you 10 when count is 0. ?? only falls back for null and undefined, which is almost always what you actually meant.

Spread and destructuring

// Copy an object, overriding one field
const updated = { ...task, done: true };

// Copy and join arrays
const all = [...oldTasks, newTask];

// Pull fields out into variables
const { title, done } = task;
const [first, second] = tasks;

Spread makes a shallow copy — nested objects are still shared. For a task with only strings and booleans that is fine; for anything nested, know that changing a nested value changes both copies.

Control flow

if (count === 0) {
  console.log('none');
} else if (count === 1) {
  console.log('one');
} else {
  console.log('many');
}

const label = count === 1 ? 'task' : 'tasks';   // ternary

// Loop over values
for (const task of tasks) {
  console.log(task.title);
}

// Loop over an object's entries
for (const [key, value] of Object.entries(task)) {
  console.log(key, value);
}

Use for...of for arrays. for...in loops over keys including inherited ones and is a common source of surprises — avoid it.

Modules

// db.js
export async function listTasks() { ... }
export const MAX = 200;

// server.js
import { listTasks, MAX } from './db.js';
import * as db from './db.js';        // everything, namespaced

Anything not exported is private to its file. That is what makes src/db/tasks.js in this project a real boundary: readAll and writeAll are not exported, so nothing outside can touch the file directly.

In the browser, modules need <script type="module"> — which is exactly what client/index.html uses.

try {

throw new Error('Title is required');
Never catch and ignore

An empty catch {} turns a crash you could debug into wrong behaviour you cannot. Catch what you expect and can handle; let everything else through. Look at src/db/tasks.js: it catches the "file does not exist" error specifically and re-throws everything else.

2

Predict the output

Work these out on paper first, then check in the console:

console.log(1 + '1');
console.log('3' * 2);
console.log([] + {});
console.log(0 === -0);
console.log(0.1 + 0.2 === 0.3);
console.log([1, 2, 3] === [1, 2, 3]);
Show answer 
'11'      // + with a string concatenates
6         // * has no string meaning, so '3' converts to a number
'[object Object]'   // both convert to strings. JavaScript being JavaScript.
true
false     // 0.1 + 0.2 is 0.30000000000000004
false     // two different arrays; === compares identity, not contents

The last two are the ones that matter. Floating point is why you never store money as a decimal — store cents as whole numbers. And === on objects and arrays asks "is this the same object?", not "do these look alike?".

3

Write a summariser

Write summarise(tasks) that returns { total, done, remaining, percent }, where percent is a whole number and an empty array gives 0 rather than NaN.

Show solution 
function summarise(tasks) {
  const total = tasks.length;
  const done = tasks.filter(t => t.done).length;

  return {
    total,
    done,
    remaining: total - done,
    // Guard the divide: 0/0 is NaN, which then spreads through
    // everything it touches and shows up as "NaN%" on screen.
    percent: total === 0 ? 0 : Math.round((done / total) * 100),
  };
}

This is essentially what the stats memo in client/src/hooks/useTasks.js computes for the progress bar — including that divide-by-zero guard, which is why the bar is hidden entirely when there are no tasks.
