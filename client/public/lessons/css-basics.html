CSS: the basics Basics

CSS decides what the page looks like. The language itself is simple — pick elements, set properties. What takes time is learning which properties matter and why your rule is not applying.

A rule

h1 {
  color: navy;
  font-size: 2rem;
}
↑   ↑          ↑
|   property   value
selector

There are three ways to attach CSS to a page, and only one you should use:

<!-- 1. External file — do this -->
<link rel="stylesheet" href="/styles.css" />

<!-- 2. In the head — fine for a scratch file -->
<style> h1 { color: navy; } </style>

<!-- 3. Inline — avoid -->
<h1 style="color: navy">Title</h1>

An external file is cached, reusable across pages, and keeps style out of your markup. Inline styles cannot be reused, cannot express hover or media queries, and beat almost everything else in specificity — which makes them painful to override later.

Selectors

h1            { }   /* every h1 */
.card         { }   /* every element with class="card" */
#header       { }   /* the element with id="header" */
.card p       { }   /* any p inside a .card, at any depth */
.card > p     { }   /* only a p that is a DIRECT child */
.card, .panel { }   /* both — a comma means "or" */
input[type="email"] { }   /* by attribute */
a:hover       { }   /* while the mouse is over it */
li:first-child{ }   /* structural position */
.task.is-done { }   /* has BOTH classes (no space!) */
The space matters

.task.is-done means one element with both classes. .task .is-done — with a space — means an element with class is-done somewhere inside a .task. Two completely different rules that look nearly identical. When a selector mysteriously matches nothing, check this first.

Pseudo-classes you will actually use:

:hover          /* pointer is over it */
:focus          /* it has keyboard focus */
:focus-visible  /* focused via keyboard, not a click */
:active         /* being pressed right now */
:disabled       /* a disabled form control */
:checked        /* a ticked checkbox or radio */
:first-child / :last-child / :nth-child(2)
:not(.excluded) /* everything except */

Which rule wins

When two rules set the same property on the same element, CSS decides by specificity — how precisely the selector points at the element. From weakest to strongest:

SelectorStrength
p, li::beforeelement — weakest
.card, :hover, [type="text"]class
#headerid
style="..."inline — very strong
!importantoverrides everything — a last resort

If two rules have equal specificity, the one written later wins. That is why the order of your stylesheet matters, and why client/public/theme.css is loaded before client/src/styles/app.css in this project.

Keep specificity flat

Style with single classes and you rarely have a fight. The moment you write #sidebar .nav ul li a.link, the only way to override it later is something even worse. Notice that this project's stylesheets are almost entirely single class selectors — that is deliberate, not an accident.

The box model

Every element is a box with four layers, from the inside out:

┌─────────────── margin ───────────────┐   space OUTSIDE
│ ┌───────────── border ─────────────┐ │
│ │ ┌─────────── padding ──────────┐ │ │   space INSIDE
│ │ │                              │ │ │
│ │ │          content             │ │ │
│ │ │                              │ │ │
│ │ └──────────────────────────────┘ │ │
│ └──────────────────────────────────┘ │
└──────────────────────────────────────┘
.box {
  padding: 1rem;              /* all four sides */
  padding: 1rem 2rem;         /* vertical | horizontal */
  padding: 1rem 2rem 0.5rem 2rem;  /* top right bottom left, clockwise */

  border: 1px solid #ddd;
  margin: 0 auto;             /* 0 top/bottom, auto left/right = centred */
}

Then there is the one setting that fixes the box model:

*, *::before, *::after {
  box-sizing: border-box;
}

By default, width: 300px means the content is 300px, so adding padding makes the box wider than you asked for. With border-box, width means the whole visible width, padding and border included. Every project sets this on the first line and never thinks about it again — including this one, in client/public/theme.css.

Margins collapse

Two vertical margins that meet do not add up — the larger one wins. A 20px margin below one paragraph and a 30px margin above the next gives you 30px of gap, not 50px. This surprises everyone once. It does not happen with gap in flexbox or grid, which is one more reason to lay things out that way.

Display

display: block;         /* full width, stacks vertically — div, p, h1 */
display: inline;        /* flows in text, ignores width/height — span, a */
display: inline-block;  /* flows in text but accepts width/height */
display: flex;          /* lays its children out in a row or column */
display: grid;          /* lays its children out in a grid */
display: none;          /* removed entirely — takes up no space */

display: none versus visibility: hidden: the first removes the element from the layout, the second leaves a hole where it was. And note the HTML hidden attribute does the same job as display: none with no CSS at all — this project uses it for the empty state and the toast.

Colour, text, units

color: #4f46e5;               /* hex */
color: rgb(79 70 229);        /* modern syntax, no commas */
color: rgb(79 70 229 / 0.5);  /* with 50% alpha */
color: hsl(243 75% 59%);      /* hue, saturation, lightness */

HSL is worth knowing because it is the only one you can reason about: keep the hue, raise the lightness, and you have a lighter version of the same colour. Doing that in hex is guesswork. 

font-family: system-ui, sans-serif;  /* fallbacks, left to right */
font-size: 1rem;
font-weight: 600;
line-height: 1.5;        /* unitless: 1.5 × this element's font size */
text-align: center;
text-decoration: line-through;
letter-spacing: -0.02em;

Units, and when each is right:

UnitMeansUse for
pxAbsolute pixelsBorders, tiny fixed details
rem× the root font sizeFont sizes, spacing — your default
em× the current element's font sizePadding that should scale with its own text
%× the parentFluid widths
vh / vw× the viewportFull-screen sections
frA share of leftover spaceGrid columns
Why rem rather than px for text

Someone who finds small text hard to read can raise their browser's default font size. rem respects that and scales with it; px overrides it and leaves them stuck. It costs nothing to use rem and it matters to real people.

Inheritance

Some properties pass down to children automatically — color, font-family, font-size, line-height. Most do not: border, padding, background apply only where you set them.

Form controls are the famous exception — they do not inherit fonts, which is why nearly every stylesheet contains this: 

input, button, select, textarea {
  font: inherit;
}

Leave it out and your buttons quietly use the browser's font instead of yours.

Exercises

1

Style a card

Take a <div class="card"> containing an <h2> and a <p>. Give the card a white background, 1px light-grey border, 12px rounded corners, 1.5rem of padding, a max width of 24rem, and centre it on the page. Make the heading dark blue and the paragraph grey. On hover, darken the border.

Show solution 
.card {
  max-width: 24rem;
  margin: 2rem auto;
  padding: 1.5rem;
  border: 1px solid #e5e7ec;
  border-radius: 12px;
  background: white;
  transition: border-color 120ms ease;
}

.card:hover {
  border-color: #b0b6c0;
}

.card h2 {
  margin: 0 0 0.5rem;
  color: #1e3a8a;
}

.card p {
  margin: 0;
  color: #6b7382;
}
2

Win a specificity fight

Given this HTML and CSS, what colour is the text? Work it out before testing.

<p id="intro" class="lead highlight">Hello</p>

p            { color: black; }
.lead        { color: blue; }
.highlight   { color: green; }
#intro       { color: red; }
p.lead       { color: purple; }
Show answer

Red. The id selector outranks everything else here. Below that, p.lead (element + class) beats a lone class; between .lead and .highlight, which tie, .highlight wins by being written later. Note that the order of classes in the HTML attribute makes no difference at all — only the order in the stylesheet.

3

Feel the box model

Make a div 300px wide with 20px padding and a 5px border. Measure its real width in DevTools. Now add box-sizing: border-box and measure again. Explain the two numbers.

Show answer

First 350px — 300 content + 40 padding + 10 border. Then exactly 300px, because border-box makes the padding and border fit inside the declared width, squeezing the content area to 250px. The second behaviour is what everyone expects "width" to mean, which is why every project turns it on globally.
