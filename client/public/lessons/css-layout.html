Layout: flexbox and grid Basics

Layout used to be the hardest part of CSS. Flexbox and grid replaced all of the old tricks, and between them they handle essentially everything. The only real question is which of the two you want.

Choosing between them

  • Flexbox lays things out along one axis — a row or a column. The children decide how much room they need.
  • Grid lays things out in two — rows and columns at once. The container decides the shape.

Rule of thumb: a toolbar, a list, a card's contents, a button with an icon next to text — flexbox. A page shell, a photo gallery, a dashboard — grid. Mixing them is normal; this site's shell is a grid whose sidebar is a flex column.

Flexbox

Set display: flex on the parent and its direct children become flex items, laid out in a row. 

.toolbar {
  display: flex;
  gap: 0.5rem;               /* space BETWEEN items */
  align-items: center;       /* cross axis: vertical here */
  justify-content: space-between;  /* main axis: horizontal here */
}

The two axes

This is the concept that makes flexbox click. The main axis is the direction items flow; the cross axis is perpendicular to it. justify-content always works along the main axis and align-items along the cross axis.

With flex-direction: row (the default), main is horizontal. Flip to column and main becomes vertical — and now justify-content moves things up and down. That swap is why the properties feel arbitrary until it clicks. 

flex-direction: row | row-reverse | column | column-reverse;

justify-content: flex-start | center | flex-end
               | space-between   /* first and last pinned to the edges */
               | space-around
               | space-evenly;

align-items: stretch   /* default: equal heights */
           | flex-start | center | flex-end | baseline;
Centring, finally solved

Perfect centring in both directions used to take a hack. Now it is three lines: display: flex; align-items: center; justify-content: center; — or, for a single child, display: grid; place-items: center;, which is what the icon buttons in this project use.

How items share space

.item {
  flex-grow: 1;     /* take a share of leftover space */
  flex-shrink: 1;   /* give up space when crowded */
  flex-basis: auto; /* starting size before grow/shrink */

  flex: 1;          /* shorthand for 1 1 0 — "share equally" */
}

The pattern you will use most:

.composer {
  display: flex;
  gap: 0.5rem;
}

.composer__input  { flex: 1; min-width: 0; }  /* takes the rest */
.composer__submit { }                          /* stays its natural size */
min-width: 0 — the fix you will need one day

A flex item refuses to shrink below the size of its content. So one long unbroken word or a wide table blows the whole row out and the page scrolls sideways. min-width: 0 lets the item shrink properly. When a flex layout overflows for no visible reason, this is almost always the answer — and it is why .composer__input has that line.

Wrapping

.tags {
  display: flex;
  flex-wrap: wrap;   /* onto a new line rather than squeezing */
  gap: 0.5rem;
}

By default flex items never wrap; they just get narrower until they cannot. Add flex-wrap: wrap for anything that could be a long list.

Grid

.layout {
  display: grid;
  grid-template-columns: 17rem 1fr;
  min-height: 100vh;
}

That is this page's shell: a fixed 17rem sidebar and a content column taking everything left over. The fr unit means "a share of the free space", and it is what makes grid layouts survive odd window sizes where percentages break. 

grid-template-columns: 200px 1fr;        /* fixed + flexible */
grid-template-columns: 1fr 1fr 1fr;      /* three equal */
grid-template-columns: repeat(3, 1fr);   /* same, less typing */
grid-template-columns: 2fr 1fr;          /* one twice as wide */

gap: 1rem;
row-gap: 1rem;
column-gap: 2rem;

A gallery that responds without media queries

.gallery {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(14rem, 1fr));
  gap: 1rem;
}

Read it inside out:

  • minmax(14rem, 1fr) — each column is at least 14rem, and grows to share what is left.
  • auto-fill — fit as many of those as the container allows.

The result reflows from four columns to one as the window narrows, with no breakpoints at all. It responds to the actual space available rather than to guesses about screen sizes.

Placing items explicitly

.featured {
  grid-column: 1 / 3;   /* from line 1 to line 3 — spans two columns */
  grid-row: 1 / 3;
}

.wide {
  grid-column: span 2;  /* two columns, wherever it lands */
}

Grid counts lines, not columns, so a three-column grid has four lines. 1 / 3 means "start at line 1, end at line 3" — which covers two columns. Off-by-one confusion here is normal; DevTools has a grid overlay that draws the numbered lines on the page, and it makes this obvious.

Positioning

position: static;    /* the default — normal flow */
position: relative;  /* nudge from its normal spot; keeps its space */
position: absolute;  /* removed from flow; positioned within the nearest
                        positioned ancestor */
position: fixed;     /* positioned against the viewport; stays on scroll */
position: sticky;    /* normal until it hits a threshold, then sticks */

The rule people miss about absolute:

.card   { position: relative; }   /* ← the anchor */
.badge  { position: absolute; top: 0.5rem; right: 0.5rem; }

An absolutely positioned element is placed relative to its nearest ancestor that has a position other than static. Forget to make the parent relative and your badge flies to the corner of the page instead of the corner of the card.

sticky is the quiet hero — it needs an offset to do anything:

.sidebar {
  position: sticky;
  top: 0;            /* required, or it never sticks */
  height: 100vh;
  overflow-y: auto;
}

That is exactly how this page's sidebar stays put while the lesson scrolls, and it is four lines instead of the JavaScript scroll listener people used to write.

Stacking

z-index: 10;

Higher numbers sit in front — but only among positioned elements, and only within the same stacking context. Certain properties (transform, opacity below 1, filter) create a new context, which traps children inside it. That is why a z-index: 9999 sometimes refuses to come to the front: it is competing inside a box, not on the page. Keep a small, deliberate set of z-index values rather than escalating.

Exercises

1

A navigation bar

Build a bar with a logo on the left and three links on the right, vertically centred, with even spacing between the links. Flexbox only, and no fixed widths.

Show solution 
<header class="bar">
  <div class="logo">Acme</div>
  <nav class="links">
    <a href="#">Home</a>
    <a href="#">Docs</a>
    <a href="#">About</a>
  </nav>
</header>

<style>
.bar {
  display: flex;
  align-items: center;
  justify-content: space-between;
  padding: 1rem;
}

.links {
  display: flex;
  gap: 1.5rem;
}
</style>

Two flex containers, one nested in the other. That nesting is the normal way to build layouts — not one clever container doing everything.

2

A responsive gallery

Lay out twelve cards so they fill the width in as many columns as fit, each at least 12rem wide, with a 1rem gap — and no media queries. Resize the window and watch the column count change.

Show solution 
.gallery {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(12rem, 1fr));
  gap: 1rem;
}

Try swapping auto-fill for auto-fit with only three cards in a wide window. auto-fill keeps the empty columns and the cards stay narrow; auto-fit collapses them so the three cards stretch to fill the row.

3

Read this page's layout

Open client/src/styles/library.css and find .layout. Why is the second column 1fr rather than a percentage? Then find what happens to .sidebar below 60rem — how does a two-column layout become a slide-out drawer?

Show answer

1fr means "whatever is left after the sidebar takes its 17rem". A percentage cannot express that — you would have to recalculate it for every window width, and it would break the moment the sidebar width changed.

In the media query the grid drops to a single column, so the sidebar is no longer part of the flow at all. It becomes position: fixed and is pushed off-screen with transform: translateX(-100%); adding the is-open class slides it back to zero. Animating transform rather than left keeps the movement on the GPU, which is the difference between a smooth slide and a stuttering one.
