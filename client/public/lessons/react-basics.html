Components and JSX Basics

React does one thing: it keeps the screen in step with your data. You describe what the page should look like for a given state, and React works out which parts of the DOM to change.

What problem it solves

In the DOM lesson you wrote this pattern by hand — keep the data in one place, write a render() that draws the whole screen from it, and call render() after every change: 

let tasks = [];

function render() {
  list.replaceChildren(...tasks.map(taskElement));
  countEl.textContent = tasks.filter(t => t.done).length + ' done';
}

tasks.push(newTask);
render();

That works, and it is genuinely the right approach at small scale. It has one problem: redrawing everything means the browser rebuilds elements that did not change. With twelve tasks nobody notices. With a thousand rows and a text field the user is typing into, they do.

React lets you keep writing in that style — describe the whole screen, every time — while it works out the minimum set of DOM changes needed. That is the entire trade.

A component

A component is a function that returns markup:

function Greeting() {
  return <p>Hello</p>;
}

Two rules the language enforces: the name must start with a capital letter — that is how React tells your components from built-in tags like <p> — and it must return a single root element.

JSX is not HTML

That <p>Hello</p> is JSX, and no browser can run it. A build step compiles it into ordinary function calls: 

// what you write
<p className="lead">Hello</p>

// what the browser actually receives
React.createElement('p', { className: 'lead' }, 'Hello')

Knowing that explains most of JSX's oddities. It is JavaScript, so the attribute names are the DOM's property names rather than HTML's:

Braces put JavaScript inside markup

function Greeting() {
  const name = 'Kier';
  const hour = 9;

  return (
    <div>
      <p>Hello, {name}</p>
      <p>You have {2 + 3} tasks</p>
      <p>{hour < 12 ? 'Good morning' : 'Good afternoon'}</p>
    </div>
  );
}

Anything inside { } is an expression — a value, not a statement. You cannot put an if or a for loop there, which is why conditions use the ternary ? : and lists use .map().

React escapes what you interpolate

{task.title} is inserted as text, always. A task called <img src=x onerror=alert(1)> is shown, not run. This is the one real security improvement React gives you over hand-written DOM code: the safe behaviour is the default, and you have to go out of your way — with dangerouslySetInnerHTML — to lose it.

Props

Props are the arguments a component receives. They flow one way: parent to child, never back up. 

function TaskRow({ title, done }) {
  return (
    <li className={done ? 'task is-done' : 'task'}>
      {title}
    </li>
  );
}

// used as
<TaskRow title="Buy milk" done={false} />

Note the destructuring in the parameter list — { title, done }. React passes one object; pulling the fields out there saves writing props. everywhere.

Note also the two kinds of value: title="Buy milk" passes a string, and done={false} passes a real boolean. Quotes mean a string; braces mean a JavaScript value.

Lists

function TaskList({ tasks }) {
  return (
    <ul>
      {tasks.map((task) => (
        <TaskRow key={task.id} title={task.title} done={task.done} />
      ))}
    </ul>
  );
}
key is not optional, and the index is not a key

key is how React tells one item from another between renders. Without it you get a console warning; with the array index instead of a stable id, you get something worse — React reuses the wrong element when the list is filtered, sorted or has an item removed.

The classic symptom: you tick a checkbox and a different row ticks. Use an id that belongs to the data.

Conditional rendering

{error && <p className="error">{error}</p>}

{isDone ? <span>Done</span> : <span>Not done</span>}

{tasks.length === 0 && <EmptyState />}

&& works because React ignores false, null and undefined — it renders nothing for them.

The zero trap

{tasks.length && <List />} renders a literal 0 on the page when the array is empty, because 0 is falsy but is not one of the values React skips. Compare explicitly: tasks.length > 0 && …

Composition

Components nest, and that is how a page is built:

function App() {
  return (
    <>
      <Header />
      <TaskList tasks={tasks} />
      <Footer />
    </>
  );
}

<>…</> is a fragment: a wrapper that satisfies the one-root-element rule without adding a real <div> to the page. Reach for it whenever a wrapper element would only exist to keep React happy.

Exercises

1

Translate to JSX

Rewrite this HTML as a component called Card:

<div class="card">
  <label for="name">Name</label>
  <input id="name" tabindex="0" style="width: 100%">
  <button onclick="save()">Save</button>
</div>
Show solution 
function Card({ onSave }) {
  return (
    <div className="card">
      <label htmlFor="name">Name</label>
      <input id="name" tabIndex={0} style={{ width: '100%' }} />
      <button onClick={onSave}>Save</button>
    </div>
  );
}

Five changes, and each is JSX being JavaScript rather than HTML: className, htmlFor, tabIndex as a number, style as an object, and onClick taking a function rather than a string of code.

2

Spot the bugs

Three things are wrong here. Find them before reading on.

function taskList({ tasks }) {
  return (
    <ul>
      {tasks.map((task, i) => (
        <li key={i} class="task">{task.title}</li>
      ))}
    </ul>
  );
}
Show answer
  1. Lowercase name. taskList is treated as an HTML tag, not a component. It must be TaskList.
  2. class instead of className. React warns, and the styling silently does not apply.
  3. key={i}. The array index is not stable — remove the first task and every remaining key shifts, so React reuses the wrong elements. Use key={task.id}.
3

Prove the zero trap

In a component, render {items.length && <p>Has items</p>} with an empty array. What appears on the page, and why is {items.length > 0 && …} different?

Show answer

A literal 0 appears. && returns its left operand when that operand is falsy, so the expression evaluates to the number 0 — and React renders numbers. It only skips false, null, undefined and true.

items.length > 0 evaluates to false, which React skips. This is the single most common visual bug in React code, and it always looks like a stray zero nobody can account for.
