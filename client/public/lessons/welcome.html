How this works

Eighteen lessons that take you from a blank HTML file to a working fullstack application. Everything is hand-written and explained — no framework magic, no copying without understanding.

The order, and why it is that order

The library is meant to be read top to bottom. Each topic assumes the ones above it:

Topic What you can do after it
HTML Put content on a page and build a form that collects input
CSS Lay that page out and make it work on a phone and in dark mode
JavaScript React to clicks, change the page, and talk to a server
How the web works Explain exactly what travels between browser and server
Backend with Node Write the server that answers those requests
Data Store things so they survive a restart, and model them sensibly
React Let a framework keep the screen in step with your data
The project Read a whole application and know why every line is there

Each lesson starts with the basics and pushes into intermediate ground before it ends, then gives you exercises. The exercises are the part that actually teaches — reading code feels like understanding, and typing it is what proves it.

How to use a lesson

  1. Read it once without typing anything, to get the shape.
  2. Type the examples — not copy, type. The mistakes you make are the lesson.
  3. Do the exercises before opening the solution. Being stuck for five minutes is productive; being stuck for thirty is not, so peek after that.
  4. Mark it read at the bottom. Your progress is saved in this browser.
Finding your way around

Press Ctrl K — or just / — to search every word of every lesson, not only the titles. The outline on the right of a long lesson jumps between its sections, and the breadcrumb at the top gets you back out.

A scratch file for experiments

Most exercises want somewhere to try things. Make a file called scratch.html anywhere on your machine, paste this in, and open it by double-clicking. No server needed: 

<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <title>Scratch</title>
    <style>
      /* CSS experiments go here */
    </style>
  </head>
  <body>
    <!-- HTML experiments go here -->

    <script>
      // JavaScript experiments go here
      console.log('hello');
    </script>
  </body>
</html>

Press F12 to open your browser's developer tools and click the Console tab. That is where console.log output and error messages appear, and you will live there from the JavaScript lessons onward.

The example project

From the Node lessons onward, the examples come from a real application — a task tracker with a React frontend, a hand-written Node backend and a SQLite database. It is running at the demo, and its source is the repository this library lives in.

That is deliberate. Code written to be read in a tutorial is always tidier than code that has to work, and the difference is where most of the real lessons hide.

One honest caveat

The project has been rebuilt since several of these lessons were written — it now uses React and SQLite where it once used plain JavaScript and a JSON file. Every concept in the lessons still holds, and the older approaches are worth understanding precisely because they explain what the newer ones replaced. But where a lesson names a specific file, that path may no longer match what is in the repository.

One habit worth building now

When something does not work, read the error message before changing anything. Beginners tend to skip past errors and start guessing. The message almost always names the file and the line, and it is right far more often than a guess is.

Ready

Start with HTML: the basics. If you already know some HTML and CSS, skim those and slow down at Async, promises and fetch — that is where the frontend and backend meet, and it is the concept most people find genuinely hard.
