Node fundamentals Basics

Node is JavaScript running outside a browser. Same language, different powers: no document and no window, but it can read files, open network ports and talk to a database.

Two runtimes, one language

BrowserNode
Runs onThe user's machineYour server
Can read filesNoYes
Has documentYesNo
Has fetchYesYes (since v18)
Trusted with secretsNeverYes

That last row is the important one. Anything you send to the browser is readable by whoever is using it — API keys, database passwords, other people's data. Secrets live on the server and never leave it. 

node server.js      # run a file
node                # a REPL, for trying things
node --check x.js   # parse without running — a quick syntax check

Modules

There are two module systems in the wild. Use the modern one:

// ES modules (ESM) — what this project uses
import fs from 'node:fs/promises';
export function listTasks() { }

// CommonJS — older, still everywhere in tutorials
const fs = require('fs');
module.exports = { listTasks };

To get ESM you need one line in package.json:

{
  "type": "module"
}

Without it, Node treats .js files as CommonJS and import throws a confusing syntax error. That single line is the cause of most "cannot use import statement outside a module" questions.

Import paths differ from the browser

In Node you must include the file extension — import * as db from './db.js', not './db'. And built-in modules take the node: prefix (node:fs, node:path), which makes it obvious at a glance that they are not packages someone installed.

The built-ins worth knowing

fs — files

import fs from 'node:fs/promises';

const text = await fs.readFile('data.json', 'utf8');
await fs.writeFile('data.json', JSON.stringify(data, null, 2), 'utf8');
await fs.mkdir('data', { recursive: true });
await fs.rm('old.txt');

Always import from node:fs/promises, not node:fs. The plain version is callback-based and leads straight to nested callbacks; the promises version works with await.

Two details from db.js in this project. Passing 'utf8' gets you a string; leave it off and you get a Buffer of raw bytes. And recursive: true on mkdir means "create it, and do not complain if it already exists", which saves an if-exists check.

path — file paths

import path from 'node:path';

path.join(__dirname, 'data', 'tasks.json');
path.extname('styles.css');    // '.css'
path.basename('/a/b/c.txt');   // 'c.txt'
Never build paths with string concatenation

dir + '/' + file breaks on Windows, doubles up separators, and lets .. sneak through. path.join normalises all of that. This is not pedantry — path handling done by hand is a real source of security holes, as the static file server in this project shows.

ESM has no __dirname, so you reconstruct it:

import { fileURLToPath } from 'node:url';

const __dirname = path.dirname(fileURLToPath(import.meta.url));

import.meta.url is the current file's own location as a URL. The point of this dance is that your paths then work no matter which directory someone runs node from.

http — a server

import http from 'node:http';

const server = http.createServer((req, res) => {
  res.writeHead(200, { 'Content-Type': 'text/plain' });
  res.end('Hello');
});

server.listen(3000, () => {
  console.log('http://localhost:3000');
});

That is a complete web server. createServer takes one function and Node calls it for every incoming request, handing you two objects:

  • req — what was asked for: req.method, req.url, req.headers, and the body as a stream.
  • res — how you answer: res.writeHead(status, headers) then res.end(body).

That request/response pair is the whole of backend work. Everything else is organisation.

crypto — ids

import crypto from 'node:crypto';

crypto.randomUUID();   // 'f81d4fae-7dec-11d0-a765-00a0c91e6bf6'

Why not 1, 2, 3? Because two requests arriving at the same moment could both read "the highest id is 4" and both decide to be 5. Random ids sidestep that entirely, and they do not leak how many records you have.

Reading a request body

This is the part that surprises people:

async function readJsonBody(req) {
  const chunks = [];
  let size = 0;

  for await (const chunk of req) {
    size += chunk.length;
    if (size > 1_000_000) throw new Error('Request body too large');
    chunks.push(chunk);
  }

  const raw = Buffer.concat(chunks).toString('utf8');
  return raw ? JSON.parse(raw) : {};
}

A request body does not arrive all at once. It comes in pieces as they travel across the network, so req is a stream and you loop over the chunks as they land.

The size cap matters. Without it, one request with an endless body eats all your server's memory until it dies. Express's express.json({ limit: '1mb' }) is doing exactly this for you.

Async on the server

Node runs your JavaScript on a single thread — the same model as the browser. Anything slow must be asynchronous, or the whole server stops answering everyone while it waits. 

// Fine: this thread is free to serve other requests while it waits
const data = await fs.readFile('big.json', 'utf8');

// Catastrophic: nothing else can happen until this finishes
const data = fsSync.readFileSync('big.json', 'utf8');

The ...Sync functions exist and are fine in a build script or at startup. Inside a request handler they are a bug: one slow read freezes every other user.

Environment and arguments

process.env.PORT           // environment variables
process.argv               // command-line arguments
process.exit(1);           // quit with an error code
console.error('bad');      // writes to stderr, not stdout
const PORT = process.env.PORT ?? 3000;

Environment variables are how configuration and secrets reach a server without being written in the code. A database password in a source file ends up in version control, and from there in everyone's laptop backup.

Packages

npm init -y            # create package.json
npm install express    # add a dependency
npm install --save-dev nodemon
npm run start          # run a script from package.json
{
  "scripts": { "start": "node server.js" },
  "dependencies": { "express": "^4.19.2" }
}
  • node_modules/ holds the installed code. Never commit it — it is rebuilt from the lock file.
  • package-lock.json pins exact versions. Always commit it, or two machines get different code from the same package.json.
Why this project installs nothing

Every dependency is code you did not read running with your privileges, and a package with fifty transitive dependencies is fifty chances for that to go wrong. This project has zero on purpose — partly to teach the built-ins, and partly because "do I actually need this?" is a question worth asking every time.

Exercises

1

A file-backed counter

Write counter.js that reads a number from count.txt, adds one, writes it back and prints it. Run it three times. It must work on the first run, when the file does not exist yet.

Show solution 
import fs from 'node:fs/promises';

const FILE = 'count.txt';

async function readCount() {
  try {
    return Number(await fs.readFile(FILE, 'utf8'));
  } catch (err) {
    // ENOENT means the file is not there — on a first run that is
    // expected, not an error. Anything else is a real problem.
    if (err.code === 'ENOENT') return 0;
    throw err;
  }
}

const count = (await readCount()) + 1;
await fs.writeFile(FILE, String(count), 'utf8');
console.log(count);

That try/catch is the same pattern as readAll in db.js: handle the one error you expect, re-throw the rest.

2

A server in ten lines

Write a server on port 3001 that answers / with "Hello", /time with the current time, and anything else with a 404. Log every request.

Show solution 
import http from 'node:http';

http.createServer((req, res) => {
  console.log(req.method, req.url);

  if (req.url === '/') {
    res.writeHead(200, { 'Content-Type': 'text/plain' });
    res.end('Hello');
  } else if (req.url === '/time') {
    res.writeHead(200, { 'Content-Type': 'text/plain' });
    res.end(new Date().toISOString());
  } else {
    res.writeHead(404, { 'Content-Type': 'text/plain' });
    res.end('Not found');
  }
}).listen(3001, () => console.log('http://localhost:3001'));

Note that you must restart Node to see a change — unlike a browser, there is no reload. That is what node --watch server.js is for.

3

Feel the blocking

Add a /slow route that runs a busy loop for three seconds (while (Date.now() - start < 3000) {}). Open /slow in one tab and immediately / in another. What happens, and why?

Show answer

The second tab hangs until the first finishes. One request froze the entire server for everybody — because Node runs your JavaScript on one thread, and a busy loop never gives it up.

This is the difference between waiting and working. await fs.readFile(...) waits, and the thread is free to serve other requests meanwhile. A busy loop, a synchronous read, or a heavy calculation works, and nothing else can happen. When people say Node is bad at CPU-heavy tasks, this is what they mean.
